# نبتة الاستلام السريع

تطبيق Android مستقل لموظف الاستلام من الموردين. يعمل عبر بوابة Cloudflare الآمنة الموجودة في التطبيق، ولا يحمل في APK مفتاح Cloudflare أو عنوان قاعدة البيانات أو سرّ النفق.

## ما الذي يسجله

- البحث أو مسح باركود الصنف ثم إضافته مباشرة إلى فاتورة توريد واحدة.
- إنشاء صنف جديد عند عدم وجوده، مع توليد باركود القطعة تلقائيًا عند تركه فارغًا؛ ويمكن تعريف كرتونة وباركودها اختياريًا.
- اختيار مورد مسجل أو إضافته، مع رقم فاتورة المورد الاختياري.
- إدخال الكمية فرطًا أو كراتين، سعر الشراء، سعر البيع، وتاريخ صلاحية اختياري لكل سطر.
- حفظ طلب التوريد محليًا عند عطل الاتصال وإرساله لاحقًا بنفس مفتاح العملية؛ لذلك لا تتكرر الفاتورة عند فقد الرد.
- واجهة استلام على نمط بطاقة المورد وبطاقات الأصناف: ملخص للكرتونة والفرط والأسعار، وتوسعة لتعديل التفاصيل عند الحاجة، ثم مراجعة نهائية قبل الاعتماد.
- تحقق قبل الاعتماد من الكمية وسعر الشراء وسعر البيع، وتنبيه عند إدخال تاريخ صلاحية غير مكتمل أو غير صحيح.
- خيار طباعة إيصال الاستلام يسجل طلبًا واحدًا داخل نفس معاملة الفاتورة؛ ويطبعه جهاز نبتة Windows الرئيسي فقط على طابعة الإيصالات المضبوطة مثل XPrinter.

## التكامل

التطبيق يمر عبر `nabta-inventory-scanner-relay` في Cloudflare إلى جهاز نبتة الرئيسي. تتطلب عمليات إنشاء صنف واستلام توريد خادم نبتة الرئيسي وCloudflare Tunnel متصلين؛ نواة Cloudflare لا تنفذ بعد معاملات توريد مستقلة، لذا لا توجد كتابة مالية سحابية غير مكتملة.

يلزم تثبيت إصدار Windows المتوافق `0.2.25` على الجهاز الرئيسي لكي يلتقط أوامر طباعة الاستلام. التطبيق لا يصل إلى الطابعة أو مفتاح Cloudflare مباشرة، ولا يعيد النظام الطباعة تلقائيًا عند نتيجة غير مؤكدة لتجنب النسخ المكررة.

## البناء

من جذر المشروع، مع Android SDK وJDK 17:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot'
$env:ANDROID_HOME = 'C:\Users\ahmed\AppData\Local\Android\Sdk'
.\apps\nabta-inventory-scanner\gradlew.bat -p .\apps\nabta-quick-receipt :app:assembleDebug
```

الناتج: `app/build/outputs/apk/debug/app-debug.apk`.
