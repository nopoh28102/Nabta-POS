# ماسح مخزون نبتة للأندرويد

تطبيق APK مستقل وسريع للمسح أو البحث عن المنتج، وقراءة السعر والتوافر، ثم:

- زيادة كمية الصنف المسجل مع حركة مخزون مدققة في نبتة.
- تعديل سعر البيع بسرعة أو تعديل بطاقة الصنف بالكامل (الاسم والتصنيف والوصف والكمية والأسعار) وفق صلاحيات الحساب.
- إضافة صنف بالقطعة أو بالوزن/السائل (كيلو أو جرام أو لتر) بالباركود والاسم والتصنيف وسعر البيع والكمية والتكلفة.
- عند تسجيل صنف بالقطعة يمكن تعريف كرتونة أو عبوة/باكت: عدد المحتويات، سعر البيع، وباركود مستقل لكلٍ منها. يبقى رصيد المخزون بالوحدات الأساسية، ويحوّل التطبيق إضافة الكراتين تلقائيًا إلى عدد الوحدات الصحيح مع حركة مخزون مدققة.
- لا يتوقف تسجيل الصنف إذا خلا باركود القطعة أو العبوة أو الكرتونة: يولّد التطبيق باركودًا رقميًا فريدًا من نبتة تلقائيًا. لكل خانة زر مستقل للمسح وزر للتوليد.
- من زر «فاتورة توريد» يمكن استلام عدة أصناف سريعًا، بسعر الجملة وسعر البيع لكل سطر، ثم تسجيل فاتورة مورد واحدة وفتح طباعة إيصال الاستلام. الفاتورة نفسها تُحفظ في نبتة وتظهر في برنامج Windows.
- بحث فوري: يعرض نتائج آخر الأصناف المحفوظة على الهاتف أولًا، ثم يحدّثها من نبتة تلقائيًا؛ البحث بالاسم العربي يتسامح مع اختلاف الهمزات.
- لا يتصل التطبيق بقاعدة البيانات إطلاقًا؛ كل العمليات تمر بخادم نبتة وصلاحيات الحساب نفسه.

## معالجة باركود العبوات والكراتين

إذا كان جسر الهاتف المنشور لا يدعم بعد مسار توليد الباركود وأعاد الخطأ `404`، يولّد التطبيق محليًا باركود EAN-13 داخليًا يبدأ بـ`209` ويكمل حفظ الصنف. لا يحدث هذا البديل إلا عند `404`؛ أما أخطاء الصلاحيات والتحقق واتصال الخادم الأخرى فتظل ظاهرة للمستخدم ولا تُخفى.

## البنية

`app/` هو تطبيق Android Kotlin/Compose.  `cloudflare-worker/` هو جسر HTTPS محدود المسارات؛ لا يحوي مفاتيح في APK ولا يسمح بالبيع أو الإدارة أو النسخ الاحتياطي.

## تشغيل وبناء APK

1. افتح مجلد `apps/nabta-inventory-scanner` في Android Studio.
2. اختر JDK 17 أو أحدث، ثم عند طلب Gradle اختر Gradle 8.13+ أو أنشئ Gradle Wrapper من Android Studio، ثم نفّذ Gradle Sync.
3. شغّل `assembleDebug` لإنتاج `app/build/outputs/apk/debug/app-debug.apk`.

تم بناء نسخة Debug قابلة للتثبيت في `app/build/outputs/apk/debug/app-debug.apk`. هذه النسخة موقعة بمفتاح Debug للاختبار الداخلي؛ إصدار توزيع نهائي يحتاج مفتاح توقيع Release مستقلًا محفوظًا خارج Git.

## نشر الجسر الآمن

من مجلد `cloudflare-worker`:

```powershell
npx wrangler deploy
npx wrangler secret put NABTA_MOBILE_ORIGIN
npx wrangler secret put NABTA_TERMINAL_RELAY_KEY
```

بعد تحديث هذا الإصدار يجب نشر الـWorker نفسه، لأنه صار يمرّر أيضًا مساري توليد الباركود وفاتورة التوريد إلى خادم نبتة.

قيمة `NABTA_MOBILE_ORIGIN` هي رابط Cloudflare Tunnel الخاص بخادم نبتة، وليست رابط قاعدة البيانات. أما `NABTA_TERMINAL_RELAY_KEY` فهو مفتاح الربط المحفوظ في إعداد اتصال Cloudflare للجهاز الأساسي. بعد النشر انسخ رابط Worker إلى خانة «رابط خدمة الهاتف الآمن» في شاشة دخول التطبيق، ثم اكتب معرّف نقطة البيع وحساب نبتة المخوّل. لا يُكتب أي مفتاح سري في الهاتف.

## ملاحظات التشغيل

- قارئ الباركود يستخدم Google Code Scanner، لذلك لا يطلب إذن الكاميرا ولا يحفظ أي صورة أو مسح.
- يحتفظ التطبيق بفهرس كامل مضغوط داخل مساحة التطبيق الخاصة، وبذا يستمر البحث بالاسم أو الباركود عند انقطاع الإنترنت أو توقف الجهاز الأساسي. كما يحتفظ بآخر 120 صنفًا في مساحة مشفّرة لتسريع بداية التطبيق.
- نبتة تظل المرجع النهائي للمخزون: إذا فشل الحفظ بسبب فقدان الشبكة فقط، تحفظ العملية مشفّرة «قيد المزامنة» وتُرسل بعد عودة نبتة وتحديث الفهرس. أخطاء التحقق أو تعارض المخزون لا تُعاد تلقائيًا حتى لا تكتب فوق بيانات جهاز آخر.
- زيادة الكمية تحتاج صلاحية مدير/مالك ومراجعة رصيد؛ الخادم يكتب حركة جرد وسجل تدقيق بدل تعديل صامت.
- إنشاء الصنف يحتاج صلاحية `PRODUCT_WRITE`.
- تعديل بطاقة الصنف والكمية يحتاج حساب مالك/مدير وصلاحية الجرد؛ يحمي الخادم العملية برقم مراجعة للمخزون لمنع الكتابة فوق تعديل جهاز آخر.
- الإنترنت وخادم نبتة والنفق يجب أن تكون متاحة وقت الحفظ. عند انقطاع الشبكة لا تحفظ العملية محليًا كي لا يحدث تكرار في المخزون.
