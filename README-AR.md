# نبتة — نظام كاشير وإدارة سوبر ماركت محلي

> قاعدة البيانات الافتراضية الآن PGlite مضمّنة داخل خادم المتجر؛ لا تحتاج إلى تثبيت PostgreSQL. تحفظ في `DATABASE_DIR` وتخدم نقطتي البيع عبر API مركزية. PostgreSQL الخارجي متاح اختيارياً فقط عند `DATABASE_MODE=postgres`.

هذه النسخة تحتوي على تطبيق الإنتاج في `apps/desktop` وخادم Fastify مع قاعدة PGlite مضمّنة في `apps/server`، مع بقاء `frontend/` كمرجع تفاعلي قديم لا يُستخدم لبيانات المتجر. ابدأ من [docs/RUNBOOK-AR.md](docs/RUNBOOK-AR.md)، واقرأ [docs/CHECKLIST.md](docs/CHECKLIST.md) لمعرفة ما تم اختباره وما يحتاج أجهزة المتجر.

للتثبيت دون أوامر راجع [دليل المثبت](docs/INSTALLER-AR.md). هذه النسخة تعمل على الجهاز نفسه فقط: تفتح البيانات المحلية تلقائيًا ولا تنشئ خدمة Windows أو اتصال شبكة أو إعداد شهادة.

## تشغيل سريع للتطوير

```text
pnpm install
pnpm build
pnpm db:migrate
pnpm --filter @nabta/server start
pnpm --filter @nabta/desktop dev
```

اضبط `.env` من `.env.example`، وأنشئ المالك من شاشة الإعداد الأولى. لا توجد بيانات دخول افتراضية. للإصدار القابل للتثبيت شغّل `pnpm package:win`؛ الناتج في `apps/desktop/release/`.

النواة تمنع إصدار الفاتورة دون الخادم، وتحفظ المسودة محليًا عند الانقطاع، وتستخدم PostgreSQL مركزيًا لنقطتي بيع. البطاقة الحالية قيد محاسبي وليست تكامل تحصيل، والطابعة/الميزان الفعليان يحتاجان إعدادًا واختبارًا على أجهزة المتجر.

تشمل النسخة الإنتاجية أيضًا شاشة المخزون والمشتريات والمرتجعات والجرد والصلاحية، استيراد/تصدير CSV بمعاينة، دفتر الموردين والعملاء، البيع الآجل بحد ائتمان، التحصيل والسداد، والنسخ الاحتياطي. يكتشف الكاشير الخادم تلقائيًا عبر LAN (UDP 47620)، ويظهر اختيار نقطة البيع عند أول دخول؛ تفاصيل الخادم اليدوية موجودة في «الإعدادات» فقط. تشغيل الخادم كخدمة Windows موثق في `scripts/windows/README-AR.md`.

## المرجع التفاعلي القديم

حزمة بداية لمتجر أو سوبر ماركت مصري: واجهة عربية RTL، سريعة وواضحة، تعمل دون تحميل مكتبات أو صور من الإنترنت. اسم نبتة هو اسم مقترح ويمكن تغييره.

## افتح الواجهة

1. فك ضغط الملف بالكامل.
2. على ويندوز افتح `START.bat`، أو افتح `frontend/index.html` بمتصفح Chrome أو Edge.
3. إذا تقيّد الحفظ عند التشغيل من ملف محلي: افتح Terminal في المجلد وشغّل `npm start` ثم افتح `http://127.0.0.1:4173`. يتطلب هذا الخيار Node.js، ولا يتطلب تثبيت حزم.

الواجهة تبدأ بشاشة البيع وبأصناف وفواتير تجريبية. تتغير الأرقام بعد العمليات؛ لا توجد اتصالات خارجية. الحفظ لكل متصفح وعلى هذا الجهاز فقط؛ قد تختلف البيانات بين تشغيل الملف مباشرة والتشغيل عبر الخادم المحلي. السلة غير المكتملة لا تحفظ بعد إغلاق الصفحة؛ علّقها لحفظها. تغيير بيانات المتجر من الإعدادات يغيّر الترويسات والفواتير.

## أعط الحزمة لكوديكس

افتح المجلد `Nabta-POS` في كوديكس على جهازك. انسخ **كل محتوى** `CODEX-PROMPT-AR.md` والصقه في المحادثة. الملفات المرفقة تحدد نطاق العمل والمعمارية والاختبارات ومراحل التنفيذ. تعليمات `AGENTS.md` توجهه للحفاظ على التصميم وتطوير النظام الفعلي.

ابدأ بإنجاز النواة: قاعدة البيانات → البيع والمخزون → الورديات والمرتجعات → الصلاحيات → الربط بين نقطتي بيع → النسخ الاحتياطي → برنامج ويندوز والطابعة. التوسع يأتي بعد اجتياز هذه النواة، وليس بمجرد عرض شاشات كثيرة.

## ما يعمل في التجربة

| الجزء | الموجود فعليًا |
|---|---|
| البيع | بحث وتصنيفات، باركود في حقل البحث، كميات قطعة/كيلو، خصم، نقدي/بطاقة، حساب الباقي |
| الفواتير | تسجيل محلي، تعليق واستئناف، عرض وطباعة عبر المتصفح، مرتجع كامل مرة واحدة |
| الأصناف | إضافة وتعديل، منع تكرار الباركود، أسعار وتكلفة وحد إعادة طلب، تصدير CSV |
| المخزون | خصم البيع وإعادة المرتجع، جرد فعلي بذكر السبب، نواقص وصلاحية واحدة للصنف |
| المشتريات | استلام صنف واحد، إضافة الرصيد، تحديث التكلفة الحالية |
| الربح | مبيعات صافية، تكلفة مسجلة عند البيع، مجمل الربح، مصروفات، صافي تقديري |
| الورديات | فتح وإغلاق، رصيد افتتاحي، نقدية متوقعة وفروق العد |
| البيانات | إعدادات، حفظ محلي، تصدير واستيراد نسخة JSON، إعادة ضبط التجربة |

## ما يحتاج تنفيذًا قبل التشغيل الفعلي

هذه **واجهة أولية تفاعلية**، وليست برنامج كاشير مكتملًا. بيانات localStorage ليست قاعدة بيانات مؤمّنة، وسجلها قابل للتعديل؛ شاشة صاحب المتجر لا تمثل صلاحيات أو تسجيل دخول حقيقيين. لا تُشغّل بها حسابات متجر فعلي.

النظام الإنتاجي يحقق قاعدة البيانات المركزية والحسابات والمعاملات الذرية والمخزون والآجل والنسخ الاحتياطي والتثبيت. أما زر البطاقة فهو قيد محاسبي فقط حتى تنفيذ تكامل بنكي فعلي، والطباعة الحرارية والميزان COM/USB والتكامل الضريبي تحتاج أجهزة ومتطلبات منفصلة. هذا القسم يصف `frontend/` المرجعي القديم فقط.

الرقم المسمى «صافي الربح التقديري» = المبيعات الصافية − تكلفة البضاعة المسجلة وقت البيع − المصروفات المسجلة. لا يحسب الضرائب أو الإهلاك أو تكلفة خسائر الجرد. تغير التكلفة عند الاستلام لا يغير تكلفة الفواتير القديمة. في النسخة الفعلية تُستخدم سياسة التكلفة المحددة في المواصفات.

النظام يساعد على كشف الفروق وتتبعها؛ منع السرقة يحتاج صلاحيات وإجراءات فعلية وجردًا ومراجعة، ولا يتحقق ببرنامج وحده.

## جرّب الواجهة

- امسح الباركود `6221000000011` في حقل البحث، أو اكتبه واضغط Enter.
- أضف الجبنة وأدخل `0.375` كجم.
- أدخل خصمًا، أتمم البيع، واختبر الباقي والطباعة.
- افتح التقارير ونفّذ مرتجعًا كاملًا. تحقق من عودة المخزون وعدم قبول إرجاع نفس الفاتورة مرتين.
- سجّل مصروفًا، ثم أغلق الوردية بعد عد النقدية.
- صدّر نسخة JSON من الإعدادات قبل إعادة الضبط.

الاختصارات: `F2` البحث، `F4` الدفع، `F8` تعليق الفاتورة، `Esc` إغلاق النافذة. الماسح المقصود في التجربة USB HID يعمل كلوحة مفاتيح ويضيف Enter. ميزان COM والباركود الموزون لا يعملان بعد.

## ملفات الحزمة

```text
Nabta-POS/
  START.bat                  فتح الواجهة على ويندوز
  README-AR.md               هذه التعليمات
  CODEX-PROMPT-AR.md         البرومبت الكامل
  AGENTS.md                 قواعد تنفيذ كوديكس
  docs/PRODUCT-SPEC-AR.md    المتطلبات وقواعد العمل
  docs/IMPLEMENTATION-PLAN.md مراحل التنفيذ
  docs/API-CONTRACT.md      عقود الخدمات المقترحة
  docs/TEST-REPORT.md        نتيجة تحقق هذه الحزمة
  frontend/index.html       الواجهة
  frontend/assets/          التصميم والمنطق وبيانات التجربة
  tests/engine.test.cjs      اختبارات قواعد البيع التجريبية
  package.json              أوامر تشغيل واختبار بدون حزم
  dev-server.cjs            خادم معاينة محلي اختياري
```

`npm test` يشغّل اختبارات النواة التجريبية. واجهة الإنتاج يمكن تحويلها تدريجيًا إلى React وTypeScript مع الحفاظ على الشكل وسلوك الاستخدام. الملفات الحالية أصلية ومخصصة لهذه الحزمة؛ لم تُنسخ شفرة من مشاريع أخرى. يمكن استلهام الأنماط الوظيفية الشائعة دون مخالفة تراخيص المشاريع.

شاهد صور المعاينة في `docs/previews/` ونتائج التحقق في `docs/TEST-REPORT.md`. اختبار المتصفح الاختياري `tests/browser-smoke.cjs` يحتاج Playwright وChromium؛ ليسا مطلوبين لفتح الواجهة. شفرة الحزمة متاحة برخصة MIT المرفقة للاستخدام والتعديل التجاري أيضًا.
> **وضع التشغيل الحالي:** الإصدار المحلي لا يعرض شاشة اتصال ولا يطلب إعداد خادم. يبدأ مخزن البيانات المضمّن تلقائياً داخل نبتة، وتظهر شاشة الدخول مباشرة بالحساب `admin` وكلمة المرور `admin`. هذا الحساب مخصص للتشغيل المحلي الأول ويجب تغييره لاحقاً عند إضافة إدارة مستخدمين.
