# ربط بوت ماسنجر مع نبتة

هذا المجلد لا يستبدل البوت الحالي ولا يتعامل مع صفحة Facebook نيابةً عنه؛ البوت الموجود لديك هو المسؤول عن التحقق من توقيع Meta `X-Hub-Signature-256` وتحويل الحوار إلى سلة مكتملة. بعد ذلك يرسل البوت الطلب إلى نبتة فقط.

## المسار الموصى به

داخل Worker البوت الحالي، انسخ دالة `submitMessengerOrder` من `src/nabta.ts` أو استوردها، ثم نادها بعد أن يجمع البوت البيانات التالية:

```ts
const response = await submitMessengerOrder(env, {
  clientOrderId: crypto.randomUUID(),
  customerName: "اسم العميل",
  customerPhone: "01xxxxxxxxx",
  deliveryAddress: "العنوان التفصيلي وأقرب علامة",
  notes: "اختياري",
  lines: [{ productId: "UUID من كتالوج نبتة", qtyMilli: 1000, saleUnit: "UNIT" }],
});
```

ضع في أسرار **Worker البوت نفسه** فقط:

- `NABTA_COMMERCE_ORIGIN`: عنوان Tunnel الخاص بنبتة، مثل `https://...trycloudflare.com` أو النطاق الدائم الذي يربطه Cloudflare Tunnel.
- `NABTA_COMMERCE_SHARED_SECRET`: نفس سر «تطبيق العملاء» المحفوظ في إعدادات Cloudflare داخل نبتة.

لا تضع أي سر في Messenger أو تطبيق العميل أو الكود الأمامي. لا تؤكد للعميل أن الطلب تم إلا إذا عاد الرد `201` أو `200`. يعيد نبتة `orderId` و`trackingToken` ويحتسب الأسعار والتوافر ورسوم التوصيل (20 ج.م حاليًا) بنفسه.

## عند تعذر تعديل كود البوت مباشرة

انشر `src/index.ts` كـ Worker مستقل، ثم أضف سرًا ثالثًا `NABTA_BOT_CONNECTOR_TOKEN`. يستدعي البوت المسار `POST /internal/nabta/orders` مع `Authorization: Bearer <token>` وبنفس JSON أعلاه. يظل البوت الأصلي مسؤولًا عن تحقق توقيع Meta قبل هذا النداء.

## ما يحدث في نبتة

1. يصل الطلب بحالة «بانتظار المراجعة» ويحجز كميته فقط.
2. تتصل بالعميل يدويًا.
3. من «الإعدادات ← طلبات العملاء أونلاين وماسنجر» اضغط «تأكيد وطباعة التجهيز».
4. تُطبع ورقة فيها العميل، الهاتف، العنوان، الأصناف ورسوم التوصيل، ومكتوب عليها صراحة أنها ليست فاتورة نهائية.
5. الفاتورة النهائية والتحصيل وحركة المخزون لا يتمان إلا من نقطة البيع عند التسليم الفعلي.
