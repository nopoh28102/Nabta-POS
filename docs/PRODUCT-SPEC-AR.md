# مواصفات نبتة

## نطاق التسليم الحالي

الحزمة الحالية: Frontend عربي متعدد الملفات + منطق تجربة + برومبت ومواصفات وخطة لكوديكس المحلي. المطلوب من كوديكس لاحقًا: بناء برنامج إنتاجي. ليس ضمن هذه الحزمة خادم مركزي أو installer أو تكامل أجهزة فعلي. الواجهة لا تحتاج npm install أو إنترنت.

## افتراضات البداية

متجر واحد في مصر، عملة EGP، واجهة RTL، Windows، نقطتا بيع على LAN، جهاز رئيسي يستضيف الخدمة والقاعدة. المستخدم يبيع قطعًا وأوزانًا حتى ثلاثة منازل عشرية. برنامج منخفض التكلفة ودون اشتراك إجباري. نظام الامتثال الضريبي يتحدد عند التطبيق الفعلي وفق حالة المتجر؛ لا يُفترض اعتماد الفاتورة المطبوعة ضريبيًا.

## التصميم

الألوان: أخضر التشغيل `#166859`، حبر `#243A3C`، خلفية `#F3F6F6`، سطح أبيض `#FFFFFF`، تنبيه `#A76B1F`، خطأ `#B3434D`. خط Tahoma المحلي للعربية مع Segoe UI كبديل؛ يمكن شحن خط عربي مرخص لاحقًا. لا تحميل خطوط خارجي يبطئ التشغيل أو يعطل العمل دون إنترنت. صور الأصناف الحالية رسومات SVG أصلية. استخدام لوحة هادئة ووزن بصري أكبر لمبلغ الدفع وزر الإتمام، وارتفاعات أزرار مناسبة للمس والكيبورد.

شريط تنقل على اليمين، محتوى منظم، في نقطة البيع المنتجات يمينًا والفاتورة يسارًا على الشاشات الواسعة. على الهاتف تتكدس الأقسام. بحث مستمر التركيز عند المسح، حالات فراغ وخطأ واضحة، dialog للأفعال الحساسة مع labels وفوكس ظاهر. احترام reduced-motion.

## السياسات المالية والمخزنية

- كل قيمة في العقد integer بالقرش؛ الوزن integer بوحدة 0.001 كيلو. Backend يستخدم decimal-safe arithmetic، ويحظر Infinity/NaN والمقادير خارج الحدود المتفق عليها.
- subtotal للسطر = سعر الوحدة × الكمية بوحدة الأساس ثم تقريب نصف لأعلى للقرش. تثبت سياسة واحدة في طبقة domain.
- خصم فاتورة بالتناسب بين الأسطر، توزيع remaining piastres بترتيب lineId ثابت. الرد الجزئي يتبع التخصيص الأصلي ويعيد آخر رد قيمة الباقي لضمان عدم ضياع/زيادة قرش.
- نظام متوسط تكلفة مرجح متحرك: القيمة الافتتاحية + قيمة الوارد تشمل مصروفات التوريد القابلة للتوزيع؛ المقسوم عليه كمية الرصيد المتاح. تكلفة الصرف تؤخذ عند التنفيذ وتُجمّد. أي تغيير شراء بعد الترحيل بقيود تصحيح لا تعديل صامت.
- FEFO لا يعني FIFO cost: يحدد الدفعة التي تُصرف أولًا، بينما التكلفة المحاسبية مرجحة. امنع البيع من دفعة منتهية طبقًا للسياسة؛ استثناء مدير إن سمح القانون والسياسة وثق صراحة.
- تكلفة رد بيع صالح = تكلفة الأصل، وتدخل ضمن القيمة المخزنية وتحسب أثر المتوسط. التالف يُسجّل إهلاكًا حتى لا تعود كمية وهمية للبيع. مشتريات مرتجعة تراعي التكلفة وحالة الرصيد وتوثق أي فرق.
- لا تخلط عدد القطع والكيلو. الحزمة لها تحويل صحيح إلى وحدة الأساس، ولا تنشئ مخزونًا ثانيًا مكررًا لها.
- صافي المبيعات = الإيراد بعد الخصم والمرتجعات دون ضريبة التحصيل إن فعلت. مجمل الربح = الصافي − صافي COGS. الصافي التقديري = المجمل − المصروفات − خسائر المخزون المعترف بها. المتبقي بعد ذلك يحتاج سياسات محاسبة كاملة.
- المشتريات ليست مصروفًا كاملًا عند الاستلام. تحصيل حساب آجل ليس إيرادًا ثانيًا. تسديد المورد ليس تكلفة مبيعات ثانية.
- تقرير يوم يعترف بالمرتجع في تاريخ ترحيله، مع إمكانية تقرير cohorted للفواتير الأصلية بعنوان مستقل.

## اتصال أكثر من كاشير

السيرفر مصدر الحقيقة، serializable/locks على أرصدة المنتجات والدفعات، lock ordering ثابت لتجنب deadlocks، retries bounded، تحقق قبل commit. كل terminal له معرف، أرقام الفاتورة يصدرها الخادم. يُسجّل idempotency response في نفس transaction؛ عند retry يرجع نفس النتيجة. terminal لا يحسب نجاحًا قبل الرد المؤكد. انقطاع LAN يحفظ draft فقط؛ لا ترحيل محلي في الإصدار الأول.

## معيار اكتمال النواة

نقطتا بيع تعملان على قاعدة واحدة؛ آخر قطعة لا تباع مرتين؛ المرتجع لا يتجاوز أصل الكمية؛ العمليات الذرية لا تترك فاتورة دون مخزون أو دفع؛ أرصدة المخزون تطابق ledger؛ إغلاق الدرج يحسب كل الحركة؛ موظف دون صلاحية يحصل على رفض من الخادم؛ تقرير الربح قابل للمصالحة؛ إعادة تشغيل وتحديث يحتفظان بالبيانات؛ نسخة احتياطية تستعاد فعليًا؛ العربية واضحة في شاشة 1366×768 وفي الإيصال. لا إطلاق فعلي قبل تحقق هذه الشروط.
