# تكامل Kashier الآمن — Nabta POS

## ما تم تنفيذه

- إعدادات Kashier منفصلة لـ TEST وLIVE، لا يسمح بحفظها إلا للمالك بعد إعادة إدخال كلمة المرور.
- تشفير المفاتيح على الخادم المحلي بخوارزمية AES-256-GCM. واجهة التطبيق لا تقرأ المفاتيح بعد حفظها.
- ربط عدة ماكينات Kashier بنقطة البيع، مع ماكينة افتراضية نشطة واحدة فقط.
- إنشاء Payment Intent قبل إرسال طلب الدفع وحجز المخزون حتى 10 دقائق، مع مفتاح idempotency وسجل محاولات وتدقيق غير قابل للتعديل.
- لا تُرحّل عملية البيع أو المخزون إلا بعد تأكيد حالة الدفع `SUCCEEDED` وربط intent بالفاتورة داخل معاملة قاعدة بيانات واحدة.
- التحقق من توقيع webhook باستخدام HMAC-SHA256، وصندوق أحداث مكرر الحماية، ومراجعة التسويات للحالات المعلقة.
- طلب استرجاع إلكتروني مقيد بالقيمة المحصلة، ولا يسمح بتجاوز المدفوع أو بإنشاء استرجاع مكرر.

## تشغيل آمن

1. ولّد مفتاحاً عشوائياً بطول 32 بايت واحفظه كـBase64URL في متغير الخادم `NABTA_PAYMENT_ENCRYPTION_KEY`.
2. شغّل ترحيلات قاعدة البيانات، ثم ادخل إلى **الإعدادات ← المدفوعات والتكاملات** بحساب المالك.
3. أدخل بيانات TEST أولاً، واربط الرقم التسلسلي الحقيقي للماكينة بنقطة البيع، ثم اختبر الاتصال.
4. بعد اختبار الحساب والماكينة مع Kashier، أدخل بيانات LIVE واحفظها لتصبح البيئة النشطة. لا تستخدم LIVE قبل استكمال هذه الخطوة.
5. ضع رابط webhook العام للـWorker وحقل `Cloudflare Relay Bearer Token` في الإعدادات. عند تشغيل **مراجعة وتسوية المعلّق** يسحب Nabta الأحداث غير المعالجة من المرحّل، ويتحقق من توقيع Kashier مرة ثانية قبل اعتمادها.

## حقول تبويب «المدفوعات والتكاملات»

| الحقل | مصدره | الغرض |
| --- | --- | --- |
| Merchant ID، Secret Key، API Key، Payment API Key | لوحة Kashier | تعريف التاجر، طلبات API، والتحقق من توقيع webhook. |
| Webhook URL | رابط Worker المنشور | إشعار Kashier الخادمي بالنجاح أو الفشل. |
| Merchant Redirect URL | رابط HTTPS تابع لك | عودة العميل بعد جلسة الدفع المستضافة؛ لا يقبل النظام `localhost`. |
| Cloudflare Event Relay URL وRelay Bearer Token | Cloudflare | تخزين أحداث webhook وسحبها الآمن عند عودة الجهاز للعمل. |
| البيئة والوسائل المفعلة والمهلة والمحاولات | إعداد مالك النظام | فصل TEST/LIVE وحصر كل وسيلة دفع في تدفقها المعتمد. |
| Serial Number للماكينة | ملصق ماكينة Kashier | ربط التحصيل الفعلي بنقطة البيع الصحيحة. |

مفتاح `NABTA_PAYMENT_ENCRYPTION_KEY` ليس حقلاً في الواجهة عمداً: هو مفتاح خادم محلي يستخدم لتشفير المفاتيح الأخرى، ولا يجوز تخزينه داخل قاعدة البيانات التي يحميها.

## حدود مقصودة قبل التشغيل الفعلي

- لا توجد أي مفاتيح أو حسابات Kashier في المستودع، لذلك لا يمكن إجراء اختبار مالي حقيقي من دون بيانات التاجر والماكينة.
- تبدأ الواجهة الحالية الدفع من ماكينة Kashier POS. جلسات الدفع عبر الإنترنت مدعومة في الخادم وتعيد رابط الجلسة؛ يجب ربط مسار فتح الرابط في جهاز العميل بعد اعتماد تدفق التشغيل المطلوب.
- InstaPay وPayment Link لا يُرسلان كعمليات مالية حتى يُعتمد من Kashier مفتاح/توقيع التدفق الخاص بالحساب. هذا منع متعمد لتجنب توليد توقيع أو تنفيذ مالي غير موثّق.
- لا تنشر Worker أو تفعّل LIVE تلقائياً؛ يلزم قرار المالك ومفاتيح البيئة الحقيقية.
