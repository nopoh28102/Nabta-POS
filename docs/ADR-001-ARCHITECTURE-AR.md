# قرارات معمارية مختصرة

## ADR-001 — قاعدة PostgreSQL مضمّنة افتراضياً

نستخدم PGlite داخل عملية خادم نبتة وعلى مجلد بيانات دائم واحد في جهاز المتجر الرئيسي. تتصل نقطتا البيع بالخادم عبر LAN ولا تفتحان ملفات القاعدة. هذا يلغي تثبيت PostgreSQL ويحافظ على SQL والمعاملات وقفل الصفوف وامتداد `pgcrypto`. يمكن اختيار PostgreSQL الخارجي لاحقاً للمتاجر الأكبر عبر `DATABASE_MODE=postgres`.

لا نشارك ملف SQLite على الشبكة ولا ننشئ قاعدة مستقلة لكل كاشير؛ كل البيع يمر عبر API المركزية ومعاملة واحدة.

## ADR-002 — حدود الثقة

الـ renderer يعرض ويطلب فقط. التحقق من السعر والمستخدم والوردية والمخزون والتكلفة والتقريب ورقم الفاتورة في الخادم داخل معاملة. Electron يعزل الواجهة ويعرض IPC محدداً.

## ADR-003 — الوحدات والمال

المبالغ integer piastres في العقود، والكميات integer milli-units. الحساب الداخلي يستخدم `bigint` وhalf-up مرة واحدة. السعر الافتتاحي يرسل كسعر وحدة والخادم يحسب القيمة.

## ADR-004 — الانقطاع والتكرار

تحفظ مسودة السلة عند غياب الخادم ولا تصدر فاتورة نهائية. كل إرسال يحمل UUID idempotency؛ عند ضياع الرد يستعلم التطبيق عن العملية قبل إعادة الإرسال.

## ADR-005 — التصحيح والسجل

لا حذف لفاتورة أو حركة مخزون نهائية. التصحيح قيد عكسي أو مرتجع مرتبط، وسجل التدقيق يكتب الفاعل والجهاز والسبب والتوقيت.
