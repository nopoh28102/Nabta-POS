# المصدر والتحديثات عبر GitHub

## البنية المعتمدة

- مستودع المصدر: `nopoh28102/Nabta-POS`.
- إصدارات ويندوز: GitHub Releases في المستودع نفسه.
- برنامج نبتة المثبت يفحص الإصدارات الرسمية بعد 15 ثانية من التشغيل، ويطلب موافقة المستخدم قبل التنزيل أو إعادة التشغيل للتثبيت.
- لا توجد رموز GitHub أو كلمات مرور في التطبيق أو المثبت أو المستودع.
- لا تُرفع قاعدة البيانات المحلية أو النسخ الاحتياطية أو ملفات الاختبار المؤقتة إلى GitHub. التحديث يحافظ على بيانات المتجر الموجودة في مجلد بيانات التطبيق.

## نشر إصدار جديد

1. عدّل رقم الإصدار في `apps/desktop/package.json` إلى رقم أعلى.
2. نفّذ الاختبارات والبناء محليًا.
3. ارفع التغيير إلى فرع `main`.
4. أنشئ وادفع وسم الإصدار المطابق، مثل `v0.1.47`.

```powershell
git tag v0.1.47
git push origin main --tags
```

سيبدأ GitHub Actions تلقائيًا على ويندوز، وينشئ مثبت NSIS وملف `latest.yml` وملف blockmap، ثم يرفعها إلى GitHub Release. تستقبل النسخ المثبتة إشعار التحديث عند التشغيل التالي.

## تنبيه أمني

يتطلب Windows توقيعًا رقميًا تجاريًا لتقليل تحذيرات SmartScreen. التحديثات تعمل بدونه، لكن يُنصح بإضافة شهادة توقيع Code Signing قبل التوزيع الواسع على أجهزة العملاء.
