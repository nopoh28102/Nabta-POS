# تشغيل نبتة على أكثر من جهاز بمخزن واحد

## ما الذي تغير؟

- الجهاز الرئيسي هو الوحيد الذي يحتفظ بقاعدة بيانات نبتة ويشغل Cloudflare Tunnel.
- كل جهاز كاشير ثانوي يتصل بواجهة API للجهاز الرئيسي عبر Cloudflare؛ لا توجد قاعدة بيانات مستقلة ولا نسخ يدوي للمخزون.
- البيع أو الاستلام أو الجرد يتم في معاملة خادم واحدة، ولذلك يظهر الرصيد الجديد مباشرة لجميع الكاشيرات ويمنع البيع الزائد.
- عند انقطاع الجهاز الرئيسي أو الإنترنت، لا يصدر الكاشير الثانوي فاتورة نهائية. هذا مقصود لحماية توحيد المخزون.

## إعداد Cloudflare مرة واحدة

1. انشر Worker الموجود في `cloudflare/pos-terminal-relay/` واربطه باسم مثل `https://pos.nabta.de5.net`.
2. في أسرار Worker أضف:
   - `NABTA_TERMINAL_ORIGIN`: `https://origin.nabta.de5.net`
   - `NABTA_TERMINAL_RELAY_KEY`: قيمة عشوائية بطول 32 حرفًا أو أكثر.
3. لا تستخدم مفتاح تطبيق العملاء لهذا Worker؛ مفتاح أجهزة نبتة منفصل.

## الجهاز الرئيسي

1. ثبّت نبتة على جهاز المخزن الذي يحتوي البيانات الحالية.
2. من الإعدادات ← ربط تطبيق العملاء وCloudflare، احفظ رابط `https://pos.nabta.de5.net` ومفتاح أجهزة نبتة نفسه المحفوظ في Worker.
3. من قسم «المخزن الموحد والكاشيرات» عيّن هذا الجهاز رئيسيًا بالرمز `281020`.
4. أعد فتح نبتة مرة واحدة بعد إضافة مفتاح أجهزة نبتة، ثم اتركه شغالًا ومتصلًا بالإنترنت.

## جهاز كاشير ثانوي

1. ثبّت نفس ملف نبتة، ولا تنقل إليه قاعدة بيانات أو نسخة احتياطية.
2. من الإعدادات ← ربط تطبيق العملاء وCloudflare ← «تحويل هذا التثبيت إلى كاشير ثانوي»، اكتب اسم الجهاز والرابط والمفتاح والرمز `281020`.
3. أعد تشغيل نبتة. سيظهر الجهاز كنقطة بيع جديدة، لكنه يستخدم مخزن الجهاز الرئيسي نفسه.

لا تشغّل Cloudflare Tunnel على الأجهزة الثانوية، ولا تستعمل مجلد قاعدة البيانات على شبكة Windows أو OneDrive.
